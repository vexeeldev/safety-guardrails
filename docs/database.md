# Safety Guardrails - Database Specification

## 1. Database

Database:

PostgreSQL

Purpose:

Store users, devices, tasks, actions, executions, verification results, and audit information.

The database must preserve enough information to reconstruct the lifecycle of a task.

---

Entities:

devices

## 10. Important Constraints

Foreign keys must be enforced.

Tasks must belong to valid users and devices.

Actions must belong to valid tasks.

Executions must belong to valid actions.

Verifications must belong to valid actions.

---

## 11. JSONB Usage

JSONB can be used for flexible action parameters.

Example:

{
  "target": "~/SafetyGuardrails/workspace/test",
  "recursive": false
}

Do not store core relational information only inside JSONB if it needs querying or indexing.

## 13. Audit Requirement

Important state transitions must be recorded.

A task should be reconstructable from:

task
+
actions
+
guardrail decision
+
approval
+
execution
+
verification
+
audit logs

---

## 14. Data Retention

Initial MVP:
Keep task history indefinitely during development.

Production retention policy can be defined later.

---

## 15. Migration

Database schema changes must use migrations.

Do not manually modify production database structure.

Migration system will be selected during backend implementation.
